# OVERBREAK — 데이터팩 → Fabric 모드 이전 계획

원본: `newserver/world/datapacks/PVP` (함수 1,175개 · 약 15,000줄) + `plugins/PvpInput` (478줄)
대상: Minecraft **26.2** · Fabric Loader 0.19.5 · Fabric API 0.160.0+26.2 · Loom 1.17 · Java 25
범위: **전부 자바로 재작성**, **서버 + 클라이언트 모드** (플레이어도 설치)

> 26.x 는 난독화가 풀린 채 배포되어 **Yarn 매핑이 없습니다.** 코드는 모장 원래 이름
> (`ServerPlayer`, `LivingEntity`, `Identifier` …)을 그대로 씁니다.

---

## 0. 원칙

1. **라이브 서버는 건드리지 않습니다.** 개발·검증은 이 프로젝트의 `run/` 폴더(Loom 이
   띄우는 별도 서버)에서만 합니다. 옮겨 붙이는 것은 사용자가 결정합니다.
2. **밸런스 숫자는 데이터팩 실측값을 그대로 가져옵니다.** 이전 도중에 수치를 바꾸지 않습니다.
   바꾸는 것은 "데이터팩이라 억지로 하던 방식" 뿐입니다.
3. **서버가 판정의 주인입니다.** 클라이언트 모드는 보여 주기(HUD·반동·연출)만 맡습니다.
   클라이언트를 조작해도 피해·쿨타임이 바뀌지 않아야 합니다.
4. 직업 하나를 옮길 때마다 **자동 테스트로 데이터팩 검증표와 같은 숫자가 나오는지** 확인합니다.

## 1. 데이터팩의 우회를 자바에서는 어떻게 푸는가

| 데이터팩에서 | 왜 그랬나 | 모드에서 |
|---|---|---|
| 좌클릭 = 플러그인 태그 `pvp.left` | 데이터팩에 좌클릭 이벤트가 없음 | 스윙 패킷 / `AttackEntityCallback` 을 서버에서 직접 받음 |
| F = 비워 둔 왼손에 아이템이 올라오면 | 손 바꾸기 통계가 없음 | `ServerboundPlayerActionPacket(SWAP_ITEM_WITH_OFFHAND)` 를 **가로채 취소**하고 스킬 발동. 아이템이 움직이지 않음 |
| Q = 떨어진 아이템 지우고 인벤토리 복구 | 버리기를 막을 수 없음 | `DROP_ITEM` 액션을 **취소**. 아이템이 애초에 안 떨어짐 |
| 구르기 방향 = 지난 틱의 자취 | WASD 를 못 읽음 | `ServerPlayer#getLastClientInput()` (방향키 실제 상태) |
| 우클릭 홀드 = 300ms 창 | 사용 통계만 있음 | `isUsingItem` / 사용 패킷 시각으로 판정 |
| 공격속도 = `entity_interaction_range` 0 으로 | 공격을 막을 방법이 없음 | 잠금 중 `AttackEntityCallback` 에서 `FAIL` |
| 스킬 피해 게이지 = 통계 전후 비교 | `/damage` 가 통계에 안 잡힘 | `ServerLivingEntityEvents.AFTER_DAMAGE` 한 곳에서 **모든** 피해를 받음 |
| 넉백 무효 = 가해자 태그 + 플러그인 이벤트 취소 | 피해 처리 안에 끼어들 틈이 없음 | 스킬 피해 원인에 "넉백 없음" 표시를 싣고 `LivingEntity#knockback` 믹스인에서 거름 |
| 돌진 = `pvp.dash_*` 점수 → 플러그인 `setVelocity` | 데이터팩이 속도를 못 줌 | 스킬 코드가 직접 `setDeltaMovement` + `hurtMarked` |
| `pvp:sheriff` 피해 타입 = **서버 재시작 필요** | 로드 시점 레지스트리 | 모드 리소스의 데이터팩으로 들어가 **월드 로드 때 항상 등록됨** |
| 정면 방어 = 플러그인 `EntityDamageByEntityEvent` | 데이터팩은 가해자를 모름 | `ServerLivingEntityEvents.ALLOW_DAMAGE` / 피해 계산 믹스인 |
| 흡수 = `AbsorptionAmount` + `max_absorption` 상한 열기 | 흡수 효과가 4 단위 | `setAbsorptionAmount` 직접 호출 |
| 정확한 회복 = 재생 효과를 N틱만 켜기 | `instant_health` 가 4 단위 | `heal(float)` |
| 쿨타임 막대 = 내구도 `damage` 20단계 | 아이템 쿨다운을 못 걺 | **바닐라 아이템 쿨다운**(`use_cooldown` 그룹) — 아이콘이 시계처럼 차오름 |
| 체력바 = `text_display` 3조각 + 보간 | 몹 머리 위에 그릴 수단이 없음 | **클라이언트 렌더링**(월드 공간 막대) |
| 반동 = `rotate` 명령 | 시야를 돌릴 수단이 이것뿐 | 서버가 반동량을 보내고 **클라이언트가 부드럽게** 시야를 올림 |
| 대사 = storage 목록 + 매크로 `tellraw` | 함수에 데이터를 둘 수 없음 | 자바 레코드 표 / 언어 파일 |
| 헤드리스 검증에 플레이어가 없음 | `@a` 경로를 몹으로 못 돌림 | Fabric API **`FakePlayer`** + GameTest — 플레이어 경로를 자동 테스트 |

### 틱 순서 (데이터팩에서 순서가 버그를 막던 곳을 그대로 보존)

1. 입력 처리 (좌/우/웅크리기/F/Q) → 스킬 시전
2. CC 타이머 감소 · 해제
3. 쿨타임 감소
4. 진행 중인 스킬 인스턴스 (채널링 → 발동 순. 회복 잔량 처리가 채널링보다 먼저)
5. 투사체 · 장판 · 파면
6. 이동 신호(돌진·제동)
7. 게이지 · 아이템 지급/회수
8. HUD 동기화 (바뀐 값만 전송)

## 5. 서버 이전 시 주의 (단계 5에서 상세화)

- Spigot 은 네더/엔드를 `world_nether` / `world_the_end` 로 쪼개 저장합니다.
  Fabric(바닐라)은 `world/DIM-1` · `world/DIM1` 에 둡니다. 옮길 때 폴더를 합쳐야 합니다.
- 데이터팩 `PVP` 는 모드와 **함께 켜 두면 안 됩니다.** 같은 입력을 두 번 처리합니다.
- 플러그인 `PvpInput` 은 Fabric 에서 로드되지 않으므로 그대로 두어도 무해하지만 치웁니다.
- 킬/데스 사이드바는 바닐라 점수판 그대로 둡니다.

### 워리어에서 데이터팩과 달라진 점
- 피의 사슬 견인: 투명 방어구 거치대에 태우는 대신 매 틱 속도를 줍니다 (거치대 정리 불필요). 속도는 데이터팩의 절반인 0.45칸/틱, 시전자 앞 1.3칸에서 수평 속도 0 으로 멈춤 (관성으로 뚫고 지나가지 않음).
- 블록 디스플레이의 블록 상태 설정이 26.2 에서 공개라 믹스인이 필요 없습니다.
- 궁극기 게이지: 시전 순간 0 이 되고, 처형장 자체 피해로 다시 찹니다 (피해 6 → 12%). 데이터팩과 같은 규칙입니다.

## 1인칭 스킬 애니메이션 (클라이언트 모드)

서버가 시전 틱에 시전자에게 `overbreak:skill_anim` (애니메이션 번호, 숨길 디스플레이 엔티티 id) 을 보냅니다.
모드가 없는 클라이언트에는 보내지 않으므로 바닐라 클라이언트도 기존 연출(디스플레이 엔티티)을 그대로 봅니다.

- `client/anim/FirstPersonAnim` — 클라이언트 틱 + 프레임 보간으로 시간을 세고 손 아이템 자세를 계산
- `client/mixin/ItemInHandRendererMixin` — 애니메이션 중 바닐라 손 변환을 버리고 위 자세로 교체
- `client/mixin/EntityRendererMixin` — 1인칭일 때만 시전자 눈앞 디스플레이 엔티티 숨김 (3인칭·다른 플레이어에게는 보임)
- 끊김(기절·사망·해제)은 번호 0 을 보내 즉시 손을 내리고 아래에서 다시 올라오게 합니다
- 시전자 몸에 붙어 나오는 휩쓸기 파티클은 모드 설치 시전자 화면에서만 뺍니다 (1인칭에서 화면 전체를 가려 도끼가 안 보였음). 다른 플레이어·모드 없는 시전자에게는 그대로 보입니다

| 스킬 | 구간 | 자세 |
|---|---|---|
| 살육 | 0~13틱 기 모으기 | 도끼가 화면 가운데로 들려 올라와 틱당 3t 도로 가속 자전, 크기 1.0→1.3, 4틱부터 떨림 증가 |
| | 13~21틱 발동 | 카메라를 축으로 오른쪽→왼쪽 틱당 72도 회전 (눈앞을 두 번 가로지름), 발동 순간 크기 1.7→1.3 |
| | 21~26틱 | 아래에서 원래 손 위치로 올라옴 |

검증: `./gradlew runClientGameTest` — 실제 클라이언트로 우클릭 시전 후 구간별 스크린샷 (`SlayAnimClientTest`).

## 어깨 너머 3인칭 카메라 (클라이언트 모드)

- 접속하면 기본 시점이 3인칭(뒤에서 보기)으로 바뀝니다. F5 로 1인칭 · 정면 3인칭 전환 가능
- 뒤에서 보기 3인칭은 캐릭터 뒤 3칸(바닐라 4칸) + 오른쪽 0.75칸. 오른쪽 · 뒤쪽 모두 벽 레이캐스트로 블록 안에 들어가지 않음
- 이 시점에서도 조준점이 보입니다 (바닐라는 3인칭에서 숨김)
- 조정: `client/camera/TpsCamera` 의 `DISTANCE_RATIO` · `SIDE`
- 조준 보정: 클라이언트가 매 틱 화면 조준선이 닿는 곳(조준점)을 서버로 보내고(`overbreak:aim`), 스킬 · 평타 방향은 `combat/Aim` 의 "눈 → 조준점" 을 씁니다. 블록 · 엔티티 선택도 같은 방향 (`LocalPlayerAimMixin`). 조준점이 없거나 5틱 넘게 오래됐거나 시선에서 45도 넘게 벗어나면 캐릭터 시선을 씁니다. 조준점이 수평 3칸 안(아래를 볼 때 발 앞 바닥)이면 시선 그대로, 10칸까지 점점 조준점 쪽으로 섞습니다 (가까울수록 카메라 옆 시차로 방향이 크게 틀어지기 때문)
- 이동: 직업이 있으면 **달리기 없음, 기본 속도 = 달리기 속도** (`Classes.SPRINT_BASE` +30%, 바닐라 달리기와 같은 곱). 클라이언트는 달리기를 시작하지 않고(`LocalPlayerSprintMixin`), 서버도 매 틱 달리기를 끔(모드 없는 클라이언트 대비). 늘 붙는 +30% 는 시야를 넓히지 않음(`AbstractClientPlayerFovMixin`) — 둔화 · 가속은 그대로 반영
- 걸음 흔들림: 화면(카메라) 흔들림 끔, 대신 1인칭 무기만 걷는 박자에 맞춰 바닐라와 같은 8자로 작게 흔들림 (좌우 · 한 걸음마다 살짝 내려감 · 기울기, `GameRendererBobMixin` → `camera/WeaponBob`). 걸음 박자는 늘 달리기 속도라 1인칭 · 3인칭 다리 흔들기 모두 0.7배로 늦춤 (`WeaponBob.CADENCE`, `AvatarRendererMixin`). 설정의 화면 흔들림 값은 건드리지 않음
- 조준 보정은 **발사체만**: 투사체 · 히트스캔 · 멀리 조준하는 스킬(연사 · 전술 로켓 · 철권포 · 피의 사슬 · 파멸의 일격 조준 · 차원 도약)은 `Aim.direction` · `Aim.yawPitch`, 근접 · 부채꼴 · 돌진(근접 평타 · 지면 분쇄 · 중력 파쇄 · 돌진 충격 · 로켓 펀치 · 지진 강타 · 과열 분사)은 보정 없는 캐릭터 정면 `Aim.facing` · `Aim.facingYawPitch`
- 새 직업을 옮길 때도 이 기준으로 고릅니다 (`caster.getYRot()` 를 직접 쓰지 않고 `Aim` 을 거침)

## 근접 평타 (좌클릭 범위 공격)

- 직업이 있는 플레이어의 바닐라 조준 근접 공격은 전부 막습니다 (`AttackSpeed`)
- 근접 직업(`meleeAllowed() = true`)은 좌클릭 스윙마다 `combat/MeleeCleave`: 조준 방향 앞 부채꼴(기본 사거리 3칸 · 폭 100도, 1칸 안은 각도 무관) 안의 적 모두에게 공격력 속성값만큼 피해, 벽 너머 제외
- 한 번 휘두르면 맞은 수와 관계없이 공격속도 잠금 · 누르고 있으면 공격속도만큼 반복
- 좌클릭 감지: 직업이 있으면 서버가 조작 모드를 켭니다(`overbreak:input_mode`). 모드 클라이언트는 좌클릭 시 바닐라 공격 · 블록 부수기 · 팔 휘두르기를 하지 않고 `overbreak:left_click` 만 보냅니다(누르고 있으면 매 틱). 서버는 공격 가능할 때만 기본 공격을 내고 애니메이션을 보냅니다 — 공격속도 대기 · 정신집중 · 기절 중 클릭은 아무 모션도 없음
- 팔 휘두르기(스윙) 모션은 조작 모드에서 아예 없습니다 (Q 버리기 등 포함, `LocalPlayerSwingMixin`). 서버도 직업이 있는 플레이어의 스윙 방송을 취소합니다
- 모드 없는 클라이언트는 예전처럼 스윙 패킷을 좌클릭으로 칩니다 (Q 와 같이 오는 스윙은 무시)
- 조작 모드에서는 좌클릭으로 블록을 부술 수 없습니다
- 직업별 조정: `PvpClass.meleeRange()` · `meleeArcDegrees()`
- 검증: `MeleeAimTest` (서버, 정면·옆 적중 / 뒤·사거리 밖 제외 / 잠금 · 조준 보정 각도 제한), `AimMeleeClientTest` (실제 클라이언트, 선택=조준점 · 서버 수신 · 좌클릭 2명 동시 적중 · 잠금)

## 3인칭 스킬 애니메이션 (클라이언트 모드)

서버가 시전자 본인 + 시전자를 보고 있는 모드 클라이언트 모두에게 `overbreak:skill_anim` (시전자 id, 번호, 숨길 디스플레이 id) 을 보냅니다.
음수 번호는 그 애니메이션 중단입니다 (살육 끊김, 피의 사슬 종료).

- `client/anim/SkillAnims` — 엔티티별 재생 시간 (1인칭 · 3인칭 공용)
- `client/anim/ThirdPersonAnim` — 팔 · 몸통 · 머리 · 다리 키프레임, 바닐라 자세와 가중치로 섞음
- `client/anim/data/*` — Blockbench 애니메이션 파일(.animation.json) 읽기 · 적용. 스킬 이름이 있는 파일이 있으면 코드 키프레임 대신 사용 (사용법: `docs/ANIMATION.md`)
- `client/mixin/AvatarRendererMixin` — 렌더 상태에 시간 · 몸 전체 회전 · 손 아이템 크기 저장
- `client/mixin/PlayerModelMixin` — 바닐라 자세가 끝난 뒤 스킬 자세로 덮어씀
- `client/mixin/ItemInHandLayerMixin` — 3인칭 손 아이템 크기 (살육 도끼)
- 살육의 디스플레이 도끼는 모드 클라이언트에서 모든 시점으로 숨기고 손 도끼 애니메이션이 대신합니다. 바닐라 클라이언트는 기존 연출을 봅니다

| 스킬 | 동작 |
|---|---|
| 살육 | 0~13틱 도끼를 머리 위로 치켜들고 떨며 도끼 1.0→1.5배 · 13~21틱 팔을 옆으로 뻗고 다리까지 몸 전체가 틱당 72도 회전, 도끼 2.5→2.0배 · 끝나면 한 바퀴 지점까지 감속 회전하며 복귀 |
| 광란의 포효 | 0~2틱 웅크림 · 5틱부터 두 팔을 위로 벌리고 고개를 젖혀 포효, 떨림 · 12틱부터 복귀 |
| 피의 사슬 | 0~2틱 팔을 머리 뒤로 젖힘 · 4틱 던짐 · 7틱부터 앞으로 뻗은 채 5틱 박자로 잡아당김(몸통 비틀기) · 서버가 사슬 종료를 알리면 복귀 |
| 광란의 처형장 | 0~5틱 두 팔 치켜듦 · 7틱 내리찍기 · 9틱부터 팔을 벌려 포효, 떨림 · 22틱부터 복귀 |

| 기본 공격 (근접 공통) | 1.5틱 당기기 · 3틱 가로 베기 · 6틱 마무리. 정방향(오른쪽→왼쪽)과 역방향(왼쪽→오른쪽)을 번갈아, 1.5초 쉬면 정방향부터. 1인칭은 카메라 축 가로 베기 후 기본 손 자세로 복귀 |

- 상체 · 하체 분리: 스킬 자세는 팔 · 몸통 · 머리에만 씁니다. 다리는 걷는 중(걷기 동작 세기 0.25 이상)이면 바닐라 걷기 그대로, 멈춰 있을 때만 스킬 스탠스. 살육 회전은 예외로 다리까지 몸 전체가 돕니다 (걷는 중이면 걸으면서 회전)
- 근접 직업은 바닐라 팔 휘두르기 방송을 취소합니다 — 공격속도 잠금 중 연타가 허공 스윙으로 남에게 보이지 않고, 실제로 휘두를 때만 기본 공격 애니메이션이 나갑니다

검증: `./gradlew runClientGameTest` (`WarriorAnimClientTest`) — 어깨 너머 · 정면 · 1인칭으로 네 스킬 · 기본 공격(정/역) · 걸으면서 살육 · 기본 공격을 쓰고 구간별 스크린샷.

## 체력 · 피해 10배 규칙 (모든 직업)

- 기본 체력 200 (바닐라 20 의 10배, \`Classes.BASE_HEALTH\`). 직업 체력 보너스도 10배 — 워리어 +10 → +100 = 체력 300
- 데이터팩 수치를 옮길 때 체력 · 피해 · 회복 · 추가체력 · 보호막은 모두 10배로 씁니다
  - 스킬 피해: \`SkillDamage.deal(대상, 시전자, 피해x10, 종류)\` — 데이터팩 5.0 피해 → 50 → \`deal(..., 500, ...)\`
  - 기본 공격: 무기 공격력 속성 10배 — 워리어 도끼 +2.6 → +35 (기본 1 + 35 = 36)
  - 회복: \`heal(40.0F)\` 처럼 10배
- 비율 · 시간 · 거리 (둔화 %, 피해 배율 %, 쿨타임, 사거리) 는 그대로
- 궁극기 게이지는 피해 10 당 2% (피해가 10배가 됐으므로 게이지 계산을 1/10 로 — 충전 속도는 예전과 같음)
- 스킬 설명(\`SkillInfo\`) · 아이템 설명도 10배 수치로 적습니다
- 바닐라 피해(낙하 · 용암 등)는 그대로라 체력 대비 1/10 로 약해집니다

## 피의 사슬 — 준비 동작 · 왼손

- 서버: 갈고리 모델이 왼손 옆 세로 원을 점점 빠르게 돌고 손에서 갈고리까지 사슬이 이어짐. 사슬은 항상 왼손(눈 기준 왼쪽 0.35 · 아래 0.4 · 앞 0.45)에서 나감
- 박자는 \`ChainSpin\` (각도 = 30t + 1.5t² 도) 하나를 서버 갈고리 · 3인칭 왼팔 · 1인칭 왼팔이 같이 씁니다

## 직업 2 · 햄머나이트

- 오른손 철퇴(\`item_model mace\`, 공격력 +44 = 45) · 왼손 방패(\`item_model shield\`, 막기 동작 없는 스킬 아이템). 체력 350 · 공격속도 0.8 · 이동속도 -10%
- 뇌진탕(패시브): 기절 · 넘어뜨림 상태의 적을 때리면 추가 피해 30(무적 무시) + CC 0.5초 연장. **한 번의 CC 에 한 번만** (\`Combatant.ccId\` — 풀려 있다가 새로 걸릴 때만 번호가 바뀜). 평타 · 돌진 충격 · 대지 진동파에서 발동
- 지면 분쇄(RMB): 0.5초 정신집중(망치를 머리 위로) → 앞 120도 · 3칸 피해 40 + 1.2초 기절. 돌진 중에 누르면 돌진이 끝나는 자리에서 곧바로 360도 내려찍기
- 돌진 충격(SHIFT): 0.3초 제자리에서 방패를 세움 → 조준 방향으로 0.55칸/틱 x 8틱. 경로 적 피해 20 + 50% 둔화 1.5초. 벽이면 멈춤 · 끝나면 제동 · 균열 지대 위에서 사용 불가
- 중력 파쇄(F): 0.5초 선동작(정신집중 아님) → 반경 4칸 적을 발밑 1칸으로 끌어옴 + 피해 20 + 70% 둔화 0.8초 → 반경 3칸 · 4초 균열 지대(이동기 봉인)

- 3인칭 · 1인칭 애니메이션: 지면 분쇄 · 중력 파쇄 = 들었다 내려찍기, 예약 분쇄 = 곧바로 내려찍기, 돌진 = 기 모으며 방패 세움 → 방패를 내민 채 돌진(1인칭은 방패를 가로로 눕혀 아래에 들어 정면이 보임), 대지 진동파 = 뒤로 빼기 → 강하게 내려치기(망치가 커짐)
